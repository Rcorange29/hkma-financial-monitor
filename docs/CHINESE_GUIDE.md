```
                    香港金融管理局 HKMA 官方公开 API
     （汇率 / 同业流动性 / 货币统计，无需密钥，https 免费获取）
                                   │
                          ① 抓取 fetch.py
              （urllib 发请求 + 失败重试退避 + 校验返回结构 + 分页）
                                   ▼
                    data/raw/*.json（原始缓存，一页一个文件）
                                   │
                          ② 清洗 transform.py
          （宽表→长表；解析数字/日期；null 记为缺失；识别月度/年度）
                                   ▼
                  ③ 入库 db.py → SQLite（hkma.db）
              （主键 dataset,metric,freq,date；UPSERT 保证幂等）
                 ┌───────────────────┼────────────────────────┐
                 ▼                   ▼                        ▼
        ④ SQL 分析（sql/）    ⑤ 数据质量 quality.py     ⑥ 可视化
        手工写的常用查询       重复/边界/缺口/MAD/跳变    Streamlit + 离线 HTML
                                                  报告写入 quality_report.json / report.html
```

**核心思想：把"采集"和"处理"分开。** 原始数据原样落盘（`data/raw`），
清洗只在内存里做，干净数据才进数据库。这样任何一步出问题，你都能回到原始
缓存排查，也可以在没有网络的情况下把整个流程重放一遍（`--offline`）。

## 二、5 个最重要的 Python / SQL 知识点

### 1. 幂等（Idempotency）与 UPSERT：重复运行不产生重复数据

"幂等"就是**同一操作做一次和做多次，结果一样**。怎么做到？给表设一个主键
（`PRIMARY KEY (dataset, metric, freq, date)`），然后用
`INSERT ... ON CONFLICT(...) DO UPDATE`（SQLite 的 UPSERT）：

- 主键不存在 → 插入（inserted）；
- 主键已存在 → 覆盖更新（updated），不新增行。

我已经实际验证：第二次运行时 `inserted=0`、全部变成 `updated`。这是数据
工程最基本的要求——定时任务每天都跑，绝不能跑出重复数据。

### 2. 长表（tidy / long format）为什么比宽表好用

API 给的是"宽表"：一行是一天，里面有 usd、gbp、jpy…… 很多列。我们把它
"熔化"成**长表**：一行只有一个指标值 `(数据集, 指标, 日期, 频率, 数值, 单位)`。

好处：新增指标不用改表结构；SQL 里 `GROUP BY metric` 就能做统计；看板里选
哪个指标就画哪条线。这是数据分析里很重要的"整洁数据"思维（每一列一个变量，
每一行一个观测）。

### 3. 用标准库就能做工程：`urllib` 重试 + 数据校验，而不是假设网络永远正常

抓取层没有用 `requests`，只用标准库 `urllib`，并处理了真实会发生的问题：

- **重试 + 指数退避**：网络抖动失败后，等待 1→2→4 秒再试，而不是立刻报错；
- **4xx 客户端错误立即停止**（再试也没用），5xx/超时才重试；
- **校验返回结构**：先看 `header.success`，再看 `result.records` 是不是列表；
  成功但 0 条数据时 `result` 为 `null`，要单独处理，不能直接 `.get` 后崩溃。

这告诉面试官：你考虑的是"它会怎么坏"，而不是"理想情况下能跑"。

### 4. 用稳健统计（MAD）找离群值，而不是随便删数据

平均值和标准差会被极端值带偏。我们用**中位数 + MAD（绝对中位差）**：

```
修正 z 分数 = 0.6745 × |x − 中位数| / MAD
```

大于 6 才标记为离群。它的特点是：哪怕有几天数值很极端，中位数也不会被拉动。
更重要的是——**所有检查只"标记"，不"删除"**。像月末隔夜 HIBOR 冲高、
总结余临时增加，这些是真实的市场行为，不是错误。异常阈值的依据（联系汇率
7.75–7.85、利率 0–30%、指数 50–200、货币存量上限）都写在
`docs/DATA_CATALOG.md` 里，而不是拍脑袋。

### 5. SQL 窗口函数 `LAG`：轻松算"相比上一期的变化"

要知道利率哪天变了，就得拿"今天的值"和"昨天的值"比较。用窗口函数：

```sql
SELECT date, value,
       LAG(value) OVER (ORDER BY date) AS prev_value
FROM observations
WHERE metric = 'disc_win_base_rate';
```

`LAG` 会在同一行里带回"上一行"的值，不用自己写复杂的自连接。配合
`GROUP BY`、`HAVING COUNT(*) > 1`（查重）、`MIN/MAX/AVG`（描述统计），
就构成了这个项目的主要 SQL 骨架。注意：SQLite 没有标准差函数，所以需要
标准差/稳健统计的部分放到 Python 的 `statistics` 里做——**要知道工具的边界**。

## 三、8 个可能的面试问题与参考回答

**Q1：用一句话介绍这个项目。**
A：我做了一个把香港金管局官方公开数据（汇率、同业流动性、货币统计）自动采集、
清洗、存入 SQLite、做数据质量检查并可视化的端到端管道；核心只用 Python 标准库，
可重复运行、幂等，还能离线重放，看板用 Streamlit。

**Q2：你怎么保证重复运行不会产生重复数据？**
A：长表上设了由 数据集、指标、频率、日期 组成的复合主键，写入用 SQLite 的
UPSERT（`INSERT ... ON CONFLICT DO UPDATE`），存在就更新、不存在才插入；每次
加载还把 inserted/updated 计数写进 `ingest_runs` 表。我实际连跑两次，第二次
inserted=0。

**Q3：为什么要把原始数据缓存下来？**
A：可审计、可复现、可离线。原始 JSON 原样落盘，任何结果都能追溯回 API 返回；
没有网络或 API 变化时，我可以用 `--offline` 完整重放；清洗逻辑有 bug 也能在
不重新请求的情况下反复调试。

**Q4：API 数据有 null（比如 2026-09 的 M1/M2/M3），你怎么处理？**
A：那是发布滞后导致的真实缺失，不是错误。我不编造数值，而是把该单元格记为
缺失（不插入值行），再用"预期日期网格"去发现这种缺口；质量报告会指出哪个月
缺了哪些指标，等官方补数据后重跑就会回填。

**Q5：那个货币统计接口里 `2025-00` 是什么？你怎么处理的？**
A：是金管局的**年度（年末）行**，月份部分用 `00` 表示，数值等于该年 12 月。
我把它规范化为 `YYYY-12-01` 并标记 `freq='annual'`，同时把 freq 加进主键，
这样年度行和月度行即使同一天也不会互相覆盖；分析时必须按 freq 过滤，不能混用。

**Q6：你怎么判断异常值？会不会误删真实的市场波动？**
A：分两层：一层是"物理上不可能/极不合理"的硬边界（比如 USD/HKD 正常不会跑出
联系汇率 7.75–7.85 太多），阈值有制度依据并留了余量；另一层是稳健 MAD 离群
（修正 z>6）。**所有结果只标记、不删除**，并在报告里说明。比如月末隔夜 HIBOR
冲高和总结余临时增加，被标记但属于真实现象。

**Q7：工作日缺口（数据没更新）你怎么判断是假期还是真出错？**
A：我用周一到周五生成预期日期网格，把缺失的工作日列出来，但不直接判错——
因为香港公众假期、台风休市也会缺。实际数据里 4/3、5/1、7/1 等缺口正好对应
公众假期。要严格判断，需要再引入官方交易日历，我在文档里写清了这一局限。

**Q8：你从数据里得到什么结论？要注意什么？**
A：在获取的窗口内，USD/HKD 一直处于 7.75–7.85 区间的偏弱半边；隔夜 HIBOR
远比 1 个月波动大、且在季末/月末临时冲高；年末年度数据能看到 3 个月 HIBOR
从 2021 年的 0.26% 升到 2023 年的 5.15% 再回落到 2025 年的 2.93%。但我只
说"观察到的关联"，不把相关性说成因果，而且样本窗口短，不能过度外推。

## 四、3 个循序渐进的小练习（用来确认你真的懂了）

**练习 1（改代码，入门）：新增一个汇率指标。**
在 `datasets.py` 的 `fx_daily` 里加入金管局提供的澳元汇率字段
（参考文档里的字段名），把它加进 `fields` 和 `metrics`（写好 label、unit、
合理 hard 区间）。然后重新运行 `run_pipeline.py --offline` 之前，先想一想：
离线缓存里没有这个字段会怎样？（提示：清洗层对"缺列"是容错的，所以你需要
先联网抓一次才能看到值。）

**练习 2（写 SQL，中等）：找出"最紧张的 5 个交易日"。**
在 `sql/` 里新写一个查询，从 `interbank_daily` 中取隔夜 HIBOR
（`hibor_overnight`），按数值从高到低排出前 5 名，带上日期。再进阶：用
`LAG` 算出每天相比前一天的变化，只输出绝对变化最大的 5 行，看看是不是都
落在月末/季末。

**练习 3（改逻辑，进阶）：把"节假日缺口"判断得更准。**
现在的缺口检查只区分工作日/周末。请你想办法接入一份"香港公众假期"清单
（可以先用一个手动维护的日期集合，或再找一个官方数据源），让
`quality.py` 把"假期导致的缺口"和"非假期的缺失"分开统计、分别输出。完成后
重新跑 `run_quality.py`，确认假期不再被计为异常缺口。
